# REPOSITÓRIO: O QUE É E PARA QUE SERVE?[cite: 3]

O que é um repositório?

Um repositório é um espaço digital dentro do GitHub utilizado para guardar, organizar e compartilhar arquivos de um projeto. Ele funciona como uma pasta, mas possui recursos especiais que permitem acompanhar todas as alterações realizadas nos arquivos. Dentro de um repositório podemos armazenar:
**Textos e documentos**.
**Imagens e vídeos**.
**Códigos de programação**.
**Arquivos de apresentação**.
**Informações e instruções sobre um projeto**.

Para que serve um repositório?

O repositório serve para organizar os arquivos de um projeto, registrar modificações, compartilhar informações e permitir que várias pessoas trabalhem juntas. Por exemplo, em um trabalho escolar, os integrantes podem utilizar um repositório para guardar a cartilha, as imagens, as pesquisas e os registros das atividades. Assim, todos conseguem acompanhar o desenvolvimento do trabalho.

[O que são repositórios?](https://docs.github.com/en/repositories/creating-and-managing-repositories/about-repositories?utm_source=chatgpt.com)

# PÚBLICO E PRIVADO: QUAL A DIFERENÇA ENTRE ELES?[cite: 3]

Repositório público: o que é?
Um repositório público é aquele que qualquer pessoa pode visualizar pela internet, mesmo sem possuir uma conta no GitHub.

Para que serve?

**Compartilhar trabalhos com outras pessoas**.

**Divulgar projetos e pesquisas**.

**Disponibilizar materiais de estudo**.

**Permitir que outras pessoas conheçam e aproveitem o conteúdo**.

Exemplo: um estudante cria uma cartilha sobre tecnologia e deixa o repositório público para que qualquer pessoa possa ler e aprender.

Repositório privado: o que é?
Um repositório privado é aquele que somente o proprietário e as pessoas autorizadas podem visualizar.

Para que serve?

**Guardar projetos com acesso restrito**.

**Compartilhar trabalhos somente com pessoas escolhidas**.

**Controlar quem pode visualizar os arquivos**.

**Desenvolver projetos sem deixar o conteúdo disponível publicamente**.

Exemplo: um grupo cria um trabalho escolar privado e permite que somente os integrantes e a professora tenham acesso.

Qual é a diferença entre repositório público e privado?

Público: **Qualquer pessoa pode visualizar, facilita a divulgação, é indicado para projetos abertos e qualquer pessoa pode conhecer o conteúdo**.

Privado: **Somente pessoas autorizadas podem visualizar, restringe o acesso, é indicado para projetos reservados e o conteúdo fica limitado aos convidados**.

Conclusão da pesquisa: O repositório é importante porque permite armazenar, organizar e compartilhar arquivos de maneira prática. A diferença entre público e privado está principalmente no acesso: o público pode ser visualizado por qualquer pessoa, enquanto o privado permite acesso somente às pessoas autorizadas.

# README: COMO CRIAR E QUAL SUA IMPORTÂNCIA?[cite: 3]

Qual a importância do README? Primeira Impressão (Portfólio): Quando um recrutador ou outro desenvolvedor entra em seu projeto, o README é a primeira coisa que ele lê. Um projeto com um bom README passa um aspecto profissional e cuidado.

Explicabilidade: Ele responde rapidamente a três perguntas fundamentais: O que esse projeto faz?, Por que ele foi feito? e Como eu faço para rodá-lo na minha máquina?

Facilidade de Colaboração: Em projetos em equipe ou de código aberto, ele orienta outros desenvolvedores sobre como instalar dependências, rodar testes e contribuir com o código sem precisarem para perguntar a cada passo.

Estrutura Básica: O que colocar nele? Um bom README costuma ter estes frascos:

Título e Descrição: Nome do projeto e um resumo curto do objetivo.

Tecnologias Utilizadas: Lista de linguagens, frameworks ou bibliotecas usadas (ex: HTML, CSS, JavaScript, React).

Pré-requisitos e Instalação: O passo a passo dos comandos para clonar o repositório e rodar o projeto localmente.

Como Usar: Exemplos práticos ou capturas de tela/GIFs demonstrando a aplicação funcionando.

Autor / Contato: Seu nome e links para seu LinkedIn ou e-mail.

# MARKDOWN: COMO FORMATAR TEXTOS NO GITHUB?[cite: 3]

O Markdown no GitHub é uma linguagem de marcação simples utilizada para formatar textos, organizar informações e criar páginas mais bonitas, claras e fáceis de compreender dentro de um repositório.

A sua principal funcionalidade é permitir que os utilizadores apresentem informações de forma organizada, sem precisarem de utilizar HTML ou conhecimentos avançados de programação.

## 1. Qual é a funcionalidade do Markdown no GitHub?
O Markdown permite:

- Formatar textos: criar títulos, subtítulos, negrito e itálico.

- Organizar informações: criar listas numeradas e listas com marcadores.

- Adicionar imagens: inserir imagens para ilustrar conteúdos.

- Criar links: direcionar os leitores para outros sites ou páginas.

- Criar tabelas: apresentar informações de forma organizada.

- Inserir códigos: apresentar exemplos de programação de maneira destacada.

- Criar documentação: explicar como funciona um projeto e como utilizá-lo.

## 2. Quais são os objetivos do Markdown para uma página no GitHub?
Os principais objetivos são:

- I. Apresentar o projeto: explicar o assunto e a finalidade do projeto.

- II. Facilitar a compreensão: tornar as informações claras e acessíveis aos visitantes.

- III. Organizar o conteúdo: dividir a informação em títulos, secções e listas.

- IV. Orientar os utilizadores: explicar como instalar, executar e utilizar o projeto.

- V. Divulgar informações: disponibilizar imagens, links e outros recursos.

- VI. Facilitar a colaboração: permitir que outras pessoas compreendam o projeto e contribuam para o seu desenvolvimento.

## 3. Exemplos de utilização do Markdown no GitHub

| Código Markdown: 1              | Funcionalidade: 2         |
| :---                            | :---                      |
| [ # Título ]                    | Cria um título principal  |
| [ ## Subtítulo ]                | Cria um subtítulo         |
| [**Texto** ]                    | Coloca o texto em negrito |
|  [ *Texto* ]                    | Coloca o texto em itálico |
| [- Item ]                       | Cria uma lista            |
| [Google. (https://google.com) ] | Cria um link              |
| ![Imagem. (imagem.png) ]        | Insere uma imagem         |
| [ --- ]                         | Cria uma linha horizontal |

O **Markdown** é uma linguagem de formatação de texto usada no GitHub para escrever arquivos README.md, documentações, issues, pull requests e comentários.

É bem simples: você usa símbolos especiais para formatar o texto.

Aqui está um guia com os principais comandos:

###1. Títulos (Headings)
Use # antes do texto. Quanto mais #, menor o título.


[ markdown ]
[ # Título nível 1 ]
[ ## Título nível 2 ]
[ ### Título nível 3 ]
[ #### Título nível 4 ]
[ ##### Título nível 5 ]
[ ###### Título nível 6 ]
Resultado:

#### Título nível 1
##### Título nível 2
###### Título nível 3
### 2. Formatação de texto

| Formatação: 1     | Markdown: 2 | Resultado: 3 |
| :---              | :---        | :---         |
| Negrito           | **texto**   | texto        |
| Itálico           | *texto*     | texto        |
| Negrito e itálico | ***texto*** | texto        |
| Tachado           | ~~texto~~   | texto        |
| Código em linha   | `código`    | código       |

### 3. Listas
